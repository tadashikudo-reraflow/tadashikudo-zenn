## はじめに

AIエージェントに RAG を足すと、最初は「固有の文脈を覚えた」ように見えます。けれど、知識ベースが更新されないままだと、数週間後には古い前提を自信ありげに返すようになります。問題は検索精度だけではなく、知識がどう増え、どう古くなるかを設計していないことです。

最近、用途の異なるエージェントを立て続けに作ったところ、どちらも同じ設計に収束しました。正本テキストを持ち、ローカルの vector index は作り直せるものとして扱い、エージェント本体は知識更新のたびに触らない、という形です。

この記事では、Raw と Index を分ける一般論ではなく、エージェントの知識ベースを「自己更新」させるための型だけに絞ります。

## 更新経路を pull と push に分ける

知識更新は、1本の経路にまとめないほうが扱いやすいです。外から入ってくる情報と、作業中に得た学びは、鮮度も粒度も違うからです。

```text
[外部ソース] -- pull --> [正本テキスト] -- rebuild --> [local vector index]
                              ^
                              |
[作業中の学び] -- push --------+
```

pull 型は、外部ソースを定期的に見に行く更新です。仕様、ドキュメント、公開ナレッジなどを差分で取り込み、正本テキストへ反映してから index を作り直します。ここで重要なのは、外部情報を直接 RAG の答えに使うのではなく、いったん人間が読めるテキストに落とすことです。

push 型は、エージェントや人間が作業中に得た学びを、その場で書き戻す更新です。たとえば「この条件では止める」「この種類の依頼は先に確認する」「この判断は危ない」といった運用知を、短いノートとして正本へ足します。

pull だけだと、自分たちの失敗や判断が残りません。push だけだと、外部の変化に遅れます。2系統を持つことで、知識ベースは「外の変化」と「内側の学び」の両方で育ちます。

## 本体コードではなくテキストを更新する

自己更新を安定させるには、知識とロジックを混ぜないことが大事です。エージェント本体は、検索して、根拠を読み、判断するだけにします。知識を増やすたびにプロンプトやコードを編集し始めると、どこで挙動が変わったのか追いにくくなります。

更新の単位は、あくまでテキストです。

```text
1. 正本テキストを追加・修正する
2. ローカルの SQLite / sqlite-vec index を再生成する
3. 次回の RAG で新しい知識が引かれる
```

この形なら、知識更新は「テキストを足す -> 再インデックス」に閉じます。エージェント本体は同じ検索インターフェースを使い続けるだけなので、知識が増えてもコード変更は不要です。

ローカル index は、壊れても作り直せる派生物として扱います。SQLite と sqlite-vec のような軽い構成なら、小さなチームや個人用途では十分扱いやすく、課金や外部サービスの状態に引きずられにくいです。ここでの主役は vector DB ではなく、再生成できる index と、失われない正本テキストの境界です。

## 信頼度メタで知ったかぶりを止める

RAG の失敗は、検索結果が外れることだけではありません。もっと危ないのは、弱い根拠を強い根拠のように扱うことです。これは、検索スコアだけでなく、知識側にメタデータを持たせることで抑えられます。

たとえば各ノートに、次のような最小メタを置きます。

```yaml
---
kind: pattern
source: observed | external | assumption
confidence: low | medium | high
risk_level: low | medium | high
last_reviewed: YYYY-MM-DD
---
```

`confidence: low` の知識が上位に来たら、エージェントは断定せず確認に倒します。`risk_level: high` の知識を引いたら、自律実行せず承認を求めます。`source: assumption` のノートは、事実ではなく仮説として扱います。

つまり、RAG の「知ったかぶり」をプロンプトだけで抑えるのではなく、知識ベースの構造で止めます。検索にヒットしたかどうかだけでなく、「それをどれだけ信じてよいか」まで一緒に返す設計にしておくと、エージェントは不確かな場面で止まりやすくなります。

## まとめ

- 知識更新は pull 型と push 型に分ける
- 更新は「正本テキストを足す -> 再インデックス」に閉じ込める
- エージェント本体は RAG で引くだけにして、知識更新でコードを触らない
- `confidence` や `risk_level` を知識側に持たせ、低信頼・高リスクでは止める
- ローカル vector index は正本ではなく、作り直せる派生物として扱う

AIエージェントの知識ベースは、一度作って終わりではなく、運用中に育つものです。自己更新の設計を先に入れておくと、賢い初期プロンプトよりも長く効く足場になります。
